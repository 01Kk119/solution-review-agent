# 取放TPM方案评审总指引

> 本文档是取放TPM知识库的唯一总入口。日常评审优先使用本文档、版本边界矩阵和结构化能力规格；原始培训、会议、XMind及逐字稿仅用于争议追溯，不作为一般阅读材料。

## 1. 目标

本指引用于判断机器人项目的取货、放货、堆叠、拆垛、货架和装卸车需求是否落在标准产品边界内，并识别：

- 标准能力与标准配置；
- 需要实物、点云或现场验证的风险；
- 版本缺口；
- 可能需要感知、控制、固件、RCS或工具开发的非标项。

“有算法”“有相似案例”“较高版本支持”都不能直接等同于当前项目无非标。

## 2. 来源与证据优先级

按以下顺序处理冲突：

1. 用户确认的取放版本映射和边界。
2. 取放规格表中的结构化参数。
3. 载具能力规格中的机械和检测参数。
4. 会议录制及逐字转写中的讲解和细分结论。
5. 培训文档中的算法原理与风险提示。
6. XMind和会议纪要中的摘要。

会议转写可能存在同音字、版本号和单位错误。数值必须回查取放规格表，不得仅引用自动纪要。

## 3. 版本映射

- `250930lite = 5.2.2`。
- `251230 = 5.3.1`，是独立版本。
- `260430 = 5.3.2`。
- 仅在取放领域，将规格表中的`160版本能力`视为5.2.2的能力和参数边界。
- 不得把160与5.2.2的等价关系扩展到操作系统、导航、调度、接口或其他产品模块。
- 不得把5.3.1的能力继承、并入或反向推定为5.3.2能力。
- 评审5.2.2或5.3.2时，规格表中的251230列不得作为能力或参数依据。

规格表“场景功能清单”中的260430主版本号仍显示为5.3.1，与本次明确口径冲突。本知识库统一按5.3.2使用，同时保留该冲突，等待源表修订。

## 4. 评审主流程

### 步骤一：确认场景

必须把“取放货”拆成具体场景：

- 地面/线库取放；
- 站台、输送线、旋转台、翻转台；
- 料笼、卡板箱或板货堆叠/拆垛；
- 横梁式、穿梭式、牛腿式或悬臂式货架；
- 双叉E车装卸车；
- 四叉装车；
- ST装卸车；
- 缠膜、窄墩、插环或其他特殊载具。

场景名称不清时不能继续做版本判断。例如“货架闭环”必须进一步说明横梁式还是穿梭式。

### 步骤二：先做0/1能力判断

先回答目标版本是否有此场景能力：

- 若明确不支持，直接登记版本缺口，并判断是否升级版本或立项开发。
- 若支持，继续检查参数边界。
- 若只有相似能力，标记待确认，不得类推。

### 步骤三：核对车型、属具和传感器

- 车型及系列；
- 双叉、四叉、夹抱等属具；
- 横移、俯仰和举升范围；
- 单M、双M、3M、叉端相机、RGBD、智能货叉等传感器；
- 传感器安装位置、检测距离、视场和遮挡。

算法与传感器架构不一致时，即使版本列“支持”，也不能直接交付。

### 步骤四：核对载具和检测特征

把每种载具拆成：

- 载具ID和入叉方向；
- 外形尺寸；
- 墩宽、墩高、墩间距；
- 插孔宽高及机械余量；
- 立柱、横梁、脚杯、脚墩和底面；
- 颜色、材质、反射率和透明度；
- 缠膜厚度、颜色、透光性、褶皱和破损；
- 变形、破损、货物遮挡及超托量。

同一物理载具的长边和短边入叉需要分别配置，不能只建一个载具参数。

### 步骤五：评估取货

取货评审回答两个问题：

1. **能否认准**：算法能否检测正确载具并得到正确位姿？
2. **能否插入**：在所有误差叠加后，货叉是否仍有安全入叉余量？

总误差至少包括：

- 感知检测误差；
- 停车或伺服控制误差；
- 载具制造公差和变形；
- 货叉、门架和举升误差；
- 地面、货架或车厢姿态误差。

### 步骤六：评估放货

先计算客户允许的放货容差，再选择：

- 普通放货/纯定位；
- 平台检测放货；
- 闭环放货。

闭环不是“检测更准”的同义词。闭环需要实时观测货叉上货物和目标对象之间的偏差，并在放货过程中持续修正。

### 步骤七：核对异常流程

至少确认：

- 检测不到怎么办；
- 模板与载具ID不匹配是否报警；
- 入叉不到位是否重试；
- 堆叠确认失败是否换库位；
- 任务失败由谁取消、重派或人工恢复；
- 车辆、RCS和外部系统状态如何对齐；
- 是否有防撞、空间检测和安全退出路径。

异常流程超出现有状态机，是常见非标开发来源。

### 步骤八：形成结论

每项需求必须输出：

- 目标版本；
- 适用车型/硬件；
- 场景和动作；
- 对应规格条目；
- 参数对比；
- 风险等级；
- 标准配置、版本缺口、待验证或疑似非标；
- 影响模块；
- 责任人和关闭条件。

## 5. 取货算法选择

| 算法/方法 | 主要识别对象 | 典型场景 | 风险边界 |
|---|---|---|---|
| 卷积托盘检测 | 墩、孔、上梁等托盘特征 | 地面、货架、拆垛、间距>50 mm线库 | 特征不足、遮挡、黑色高反、错模板 |
| 紧密空间托盘检测 | 2D投影后的紧密托盘 | 输送线、堆叠、间距<50 mm线库 | 需要模型/数据；新结构要验证 |
| 墩孔检测 | 墩和插孔 | 地面、货架、输送线 | 墩面需连贯平整，严重凹凸高风险 |
| 插孔检测 | 插孔轮廓 | 平面搬运、无可靠墩/立柱时 | 停车检测，不能把理论能力写成已验证能力 |
| 快速料笼检测 | 立柱和料笼结构 | 地面、堆叠 | 立柱尺寸、遮挡、距离和模板 |
| 纯激光缠膜检测 | 薄膜覆盖托盘的点云模板 | 地面、堆叠、输送线 | 需要训练；停车检测；不支持高度自适应 |
| 视觉缠膜检测 | 图像标注后的托盘/孔位 | 缠膜托盘 | 人眼必须能在图像中区分墩孔边界；相机和模型需验证 |
| 反光板检测 | 人工增加的反光特征 | 其他方式无法检测的非标场景 | 培训资料将其列为通常需要单独判断的方案 |

“停车检测”和“伺服检测”必须区分：

- 停车检测：车辆在固定检测点停车，检测后再执行动作。
- 伺服检测：车辆运动中持续检测并实时纠偏，通常效率更高，但对算法、控制和传感器要求更高。

## 6. 放货方法

| 方法 | 自适应方向 | 典型场景 | 非标关注 |
|---|---|---|---|
| 固定放货 | 无 | 输送线、地平库、板货、横梁式货架 | 只检测障碍物，不做末端纠偏 |
| 空间放货 | 左右 | 地平库、横梁式货架 | 新障碍物结构或更严容差 |
| 后置放货 | 前后+左右 | 地平库 | 后方障碍物和退出路径 |
| 前置放货 | 前后+左右+横梁高度 | 横梁式货架、平板飞翼车 | 多种横梁厚度可能需要开发 |
| 货位放货 | 高度 | 板货堆叠 | 依赖取货检测提供水平位姿 |
| 平板车放货 | 前后+高度，并结合两侧障碍物 | 横梁式货架、平板车 | 多方向补偿和车体空间 |
| 货柜车后置放货 | 前后+左右+偏航角 | 货柜车 | 车厢姿态、门框、登车桥和异常退出 |
| 伺服料笼堆叠 | 实时对齐 | 料笼堆叠 | 预对准、对齐、确认和安全检测 |

## 7. 专项场景检查

### 7.1 P/E料笼堆叠

5.2.2边界：

- 单款料笼水平闭环；
- 放货空间检测；
- 不支持多款料笼闭环、不完全入叉、俯仰混堆、半出叉确认和失败换库位。

5.3.2新增边界：

- 多款料笼闭环；
- 不完全入叉；
- 俯仰堆叠；
- 结构可堆叠条件下的不同料笼混堆；
- 感知半出叉堆叠确认；
- 失败后换其他库位再次尝试。

共同参数以规格表为准，包括±7 mm容差、4500 mm高度、左右/前后间距、底面结构、变形和效率成功率。

### 7.2 站台和输送线

- 5.2.2按160列：普通放货，不支持闭环。
- 约±15～20 mm时核对类墩或10×10 cm反光板。
- 约±8 mm闭环参数属于5.3.1列，不能归入5.3.2；只有5.3.2自身的专项规格或发布证据才能证明5.3.2支持。
- SL/L/R当前规格只支持普通放货。

### 7.3 高位货架

- 5.2.2：任何货架闭环均不支持。
- 5.3.2：仅支持穿梭式货架闭环；横梁式货架闭环不支持。
- 普通横梁式货架仍可使用普通放货方案，但必须满足举升高度对应的左右净空。
- 货架闭环汇总行不能覆盖货架类型细分结论。

### 7.4 装卸车

逐项核对：

- E双叉、四叉或ST；
- 装车还是卸车；
- 车厢俯仰角和翻滚角；
- 尾门宽高；
- 车内前后、左右、顶部净空；
- 登车桥宽度、坡度、承载和中心偏差；
- 车厢内货物排布是否固定；
- 最后一排货物的取放方式；
- 车辆进入、退出和失败恢复。

5.2.2不支持四叉托盘检测、四叉装车和ST卸车。E双叉基础装卸车按160参数评估。

### 7.5 缠膜托盘

必须区分：

- 纯激光：通过调整激光和模板匹配穿透/识别膜后特征，受膜厚、颜色、反光和褶皱影响。
- 视觉：通过图像标注识别孔位，要求相机图像中人眼可以看清墩孔边界。
- 四叉双托：还需核对双托高度差、前后差和角度差。

XMind给出的5.2.2/160筛查边界是总缠膜厚度小于80 μm；超过该值不得按5.2.2标准能力判断。

## 8. 非标判定

### 标准配置

- 版本、车型、属具和传感器完全匹配；
- 全部参数在规格边界内；
- 不新增算法对象、状态、接口或页面；
- 只需模板、参数、地图和任务配置。

### 待验证

- 名义上支持，但颜色、反射率、缠膜、尺寸组合或极限工况未验证；
- 需要实物、点云、展厅或现场测试；
- 不应提前承诺成功率。

### 版本缺口

- 目标版本不支持，但另一版本明确支持；
- 先比较升级版本、反向移植和单项目开发的交付风险；
- 版本缺口不自动等于已批准非标。

### 疑似非标

- 新识别对象或新模型训练；
- 新闭环、新传感器融合或新控制动作；
- 新任务参数、模板绑定或RCS流程；
- 新异常重试、换库位、人工接管或回滚；
- 参数超界且现有配置无法覆盖；
- 单项目独立程序包或代码分支。

## 10. 资料中需治理的问题

- 规格表中260430主版本号仍写为5.3.1；本指引按已确认口径映射为5.3.2。
- 规格表汇总行写260430支持“高位货架闭环”，但会议明确细化为只支持穿梭式、不支持横梁式。应把汇总行拆成货架类型。
- 自动纪要中装卸车距离单位存在厘米/毫米误写；必须回查规格表。
- 料笼底面支撑梁深度，规格表为大于4 cm；会议转写出现过4 mm，应以规格表为准。
- 缠膜边界在现有风险索引中曾出现方向相反的描述，已按XMind和截图修正为5.2.2总膜厚小于80 μm。
- “站台闭环”位于其他版本列，不能仅因260430汇总列支持站台对接就推定5.3.2具备同一闭环边界。
- 251230列属于5.3.1独立版本，不得作为5.3.2的继承能力或参数来源。
