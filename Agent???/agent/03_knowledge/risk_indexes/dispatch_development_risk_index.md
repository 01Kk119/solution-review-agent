# 调度领域开发风险索引

## 评审目标

判断 RCS 任务逻辑、交通管制、资源模型、节拍、多车协同和异常恢复能否通过标准能力与配置完成。

## 当前能力与边界

| 场景 | 当前能力索引 | 开发风险触发 |
|---|---|---|
| 相邻货架同时作业 | 相距约0.2 m时存在互锁/死锁风险 | 需要新资源模型或并发策略 |
| 移动/驶入式货架 | 当前规格标记不支持 | 核心业务依赖动态货架 |
| 末端掏货 | 可支持，但通常需要多任务编排 | 客户要求单任务原子化、特殊回滚 |
| 无路径终点 | 终点与路径约1 m边界需核对 | 布局超界或需要动态终点 |
| 单/多货物 | 货物尺寸需不超过标准车宽/车长并正确配置 | 运行中动态变更、组合规则新增 |
| Q车拖挂 | 当前规格标记不支持 | 需要拖挂任务、路径、状态和异常恢复 |
| AMR原地旋转 | 边缘场景不支持 | 场地依赖原地旋转 |
| 电梯 | 货梯有能力记录；叉车电梯存在不支持/死锁风险 | 电梯协议、排队、故障回退不同 |
| 接力/线库顺序 | 有标准能力记录 | 特殊库存、优先级、插单或回滚 |
| 停车位 | 充电位+普通位通常应大于车辆数+1，或充电位不少于车辆数 | 主路停车、容量不足、动态泊位策略 |
| 第三方调度 | 当前规格标记不支持 | 客户要求第三方接管调度 |
| 人机混行 | 无标准稳健性结论，需仿真/专项验证 | 动态人车规则、优先级或安全恢复新增 |
| 效率 | 等待时间占比建议低于约15%；需仿真验证客户节拍 | 峰值节拍无模型、任务波动大 |
| 仿真覆盖 | 取放、导航、充电失败未必被现有稳健仿真完整覆盖 | 客户要求完整故障注入与恢复指标 |

## 必取项目字段

- 车辆数、车型、任务来源和优先级。
- 路线、交叉口、共享通道、瓶颈资源、停车位和充电位。
- 峰值/平均任务量、节拍、班次、等待容忍度。
- 接口触发、任务取消、重试、幂等、回滚和人工恢复。
- 电梯、门、输送线、线库和第三方系统的资源状态。

## 风险分级建议

- 高：移动/驶入式货架、第三方调度、Q拖挂、叉车电梯或新资源模型是核心需求。
- 中：多车拥堵、峰值节拍、共享资源、故障恢复或人机混行未验证。
- 低：标准任务、交通管制和资源配置覆盖，只需仿真与联调。

## 必须回查源文件

- 任一高风险。
- 需要引用具体距离、停车位公式、等待比例或车型限制。
- 需要判断电梯、接力、线库顺序、第三方调度的正式能力状态。
