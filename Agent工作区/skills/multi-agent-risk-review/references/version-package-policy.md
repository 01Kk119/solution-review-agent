# 统一版本包规则

## 唯一版本判断权

版本适配 TPM 是项目版本和版本风险等级的唯一判断者。领域 TPM 只提供能力满足证据；非标判定 TPM、人时估算 TPM 和全局汇总 TPM 不得选择或改写版本。

## 完整版本包

版本是项目级完整版本包，包含软件、算法、硬件及配套模块。同一项目只能选择一个统一版本，不允许按模块拆分版本，也不允许混用 5.2.2 和 5.3.2。

## 固定判断顺序

| 判断条件 | 项目统一版本 | 版本风险等级 |
|---|---|---|
| 所有需求均可由 5.2.2 满足 | 5.2.2 | 低 |
| 5.2.2 不能全部满足，但 5.3.2 可以全部满足 | 5.3.2 | 中 |
| 5.3.2 仍不能全部满足 | 暂无标准版本可满足 | 高 |
| 版本证据不足 | 待确认 | 待确认 |

不得因某个模块可使用 5.2.2，就在项目已统一升级 5.3.2 后继续为该模块保留 5.2.2。

## 固定输出字段

```text
项目统一版本：5.2.2 / 5.3.2 / 暂无标准版本可满足 / 待确认
版本风险等级：低 / 中 / 高 / 待确认
5.2.2满足全部需求：是 / 否 / 待确认
5.3.2满足全部需求：是 / 否 / 未评估 / 待确认
版本上探5.3.2：是 / 否
```

字段之后可以按模块列出能力证据、差距和验证项，但不得按模块输出目标版本。
