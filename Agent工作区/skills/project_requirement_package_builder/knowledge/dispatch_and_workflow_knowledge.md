# 调度与作业流识别知识（dispatch_and_workflow）

> 用途：整理任务从哪来、车怎么调、效率怎么算、异常怎么办。
> 硬约束：效率数值只登记资料原值与计算口径，不重算不改写；策略可行性留给 TPM。

## 调度架构（必须确认的第一件事）

- 项目用 **RCS（机器人中控）** 还是 **VFS（调度系统）**？——两者架构不同，
  且与车端 IGV 软件大版本存在配套关系（版本不匹配会导致系统不兼容）。
- 是否为老项目扩容/二期（沿用既有中控？增配？）——影响版本锁定。
- 是否部署虚拟服务器/实体服务器，由谁提供。

## 任务流字段

- **任务触发**：PLC 信号 / 扫码枪 / WMS-WCS 接口 / 呼叫按钮 / PAD / 人工输入
- **任务类型与优先级**：常规搬运、峰值补差、回库、空托回收、异常转运
- **分派逻辑**：按区域、按车组、多车协同、是否允许跨任务组借车
- **充电策略**：机会充电/阈值充电、充电机数量与位置、换班衔接
- **交通管制**：单双向、会车点、防火门/窄段互斥、停车让行规则（如 stop sign 停车鸣笛）
- **异常处理**：故障车拖离、任务重派、人工介入入口（HMI/平板）、次品/异常货物流向
- **库存管理边界**：我方系统管什么（放）、客户管什么（取、盘点）——边界不清是常见风险

## 效率与仿真

登记字段：托/小时（均值、峰值）、单车节拍、车数、任务数-耗时（仿真结果）、
仿真版本与假设（车数、是否含全部流程）、缺口与补差策略（谁补、何时激活、需要哪个系统支持）。

**提示**：口头效率推算（如“每趟 X 托 × 每小时 Y 趟”）标注「会议口头信息」；
仿真结论未更新完成时记录“仿真进行中，结果待补”。
